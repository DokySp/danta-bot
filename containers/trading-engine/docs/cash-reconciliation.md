# 미분류 현금 차이 대조

계좌 현금은 증권사 관측값으로 대조한다. 주문·확인된 비용으로 설명되지 않는 차이는
`/status`와 실행·일일 보고서의 `cash_reconciliation`에 남으며 신규 매수를 막는다.
합계가 0이거나 뒤늦게 같은 금액의 수수료가 조회됐다는 이유만으로 자동 분류하지 않는다.
`/resume`도 미분류 현금·현재 위험 미검증 상태를 해제하지 않는다. 보호 감시는 계속한다.

실제 명세서로 성격을 확인한 운영자는 `config/cash-reconciliation.json`을 작성한다.
`account_scope`와 각 `adjustment_id`는 현재 상태 보고서 JSON의 값을 그대로 사용한다.
실전 파일은 root 소유, 그룹·다른 사용자 쓰기 금지, 일반 파일이어야 한다.
컨테이너 초기화는 이 선택 파일에 root 소유·0444 권한을 적용한다.
계좌 대조 때 파일을 읽고, 모든 항목이 맞을 때만 한 트랜잭션으로 적용한다.
잘못된 파일은 진단에 남기며 기존 미분류 상태·계좌 대조·보호 감시를 유지한다.

```json
{
  "schema_version": 1,
  "account_scope": "현재 상태의 계좌 범위 값",
  "resolutions": [{
    "id": "운영자가 정한 고유 근거 번호",
    "adjustment_ids": ["확인한 현금 차이 참조 값"],
    "classification": "CASH_TRANSFER",
    "source": "개인정보 없는 명세서 참조 번호",
    "internal_pnl": "-10",
    "external_flows": [{
      "at": "2026-09-21T10:00:00+09:00",
      "amount": "-200",
      "before_nav": "1000",
      "after_nav": "800"
    }]
  }]
}
```

위 숫자는 **합성 예시**다. 실제 차이 −210원 중 출금 −200원과 비용 −10원을
각각 확인한 경우를 나타낸다. 입출금 직전·직후 자산 평가는 실제 자료가 필요하다.
모르는 값을 계산으로 만들어 넣지 않는다. 같은 시각의 입출금은 합산한 한 항목을 사용한다.
입출금 시각은 선택한 현금 차이들의 마지막 관측 시각보다 늦을 수 없다.

* `CASH_TRANSFER`: 입출금. `before_nav + amount = after_nav`이고, 외부 흐름 합계와
  `internal_pnl`의 합이 선택한 현금 차이 합계와 같아야 한다.
* `INTERNAL_PNL`: 이자·배당·수수료·세금 등 내부 손익. 차이 합계와 `internal_pnl`이
  같고 `external_flows`는 빈 배열이어야 한다. 손실은 위험 계산에 남는다.
* `BROKER_CORRECTION`: 증권사의 일시적 표시 오류였다는 근거가 확인된 묶음.
  선택한 차이 합계·`internal_pnl`이 모두 0이고 외부 흐름은 없어야 한다.

반영은 현금을 다시 증감하지 않고 분류·입출금 기록만 보완한다. 적용한 근거와 원래
차이는 장부에 보존한다. 같은 `id`·내용은 재처리하지 않고, 같은 `id`의 내용 변경은
거부한다. 이후 근거는 기존 파일의 `resolutions`에 새 `id`로 추가할 수 있다.
미분류 건이 모두 해소되고 현재 계좌·시세가 확인되면 위험 계산을 다시 수행한다.
과거 불완전한 평가 이력과 실제 손실 차단은 자동 삭제하거나 초기화하지 않는다.
